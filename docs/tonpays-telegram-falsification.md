# TonPays Telegram — falsification record

The rules of `docs/tonpays-telegram-gateway-audit.md` §15 (TPTG-01..40), and the website
route's TP-01..20 from `docs/tonpays-falsification.md` again. This route refactored the HTTP
helpers, the open-attempt query and the settlement deadline that hold those rules.

Each row was reverted ALONE by `scripts/mutate-tonpays-telegram.py`, in a worktree of its own,
against its own database (`nexa_test_tptg`) with no other suite using it. Only the named tests
were run (`vitest -t`, the name escaped as a literal). The driver restores every file with
`git checkout`, refuses to continue unless the tree is byte-identical afterwards, and rebuilds
`packages/i18n` around the row that mutates it. A run in which no test executed is reported
`NO-TEST-RAN`, never killed.

The table is the final run, against the tree that carries the tests below. The first run
found four tests that could not fail, and one mutation that never reached its rule. All of
them were fixed and the whole table was run again:

- **TPTG-11** — an order settles against its own total, so a provider figure never showed. A
  top-up test now reads the ledger.
- **TPTG-19** — only the surface's check was exercised. The service is now called directly.
- **TPTG-22** — an inquiry met the empty budget first and ended the pass, so "every lease
  given back" held vacuously.
- **TPTG-40** — no case put a cadence step inside the last fifteen seconds.
- **TPTG-37p** — the substitute permission was one the support role also lacked.

**Second round: the independent review.** The review of the branch (F1–F14) and the
lead's decision on OQ-TPTG-17 added the `REV-*` rows below. Each one is the reviewer's own
surviving mutation (R01–R14) or a rule the fixes introduced, now killed by a test written for
it. The whole table, the first round's rows included, was then run again on the tree merged
with `main` (round T). That run is the one recorded here. In it, two first-round rows became
layers, because a review fix now holds the same rows a second way: TPTG-36p and TPTG-36d.
The table below explains them.

**Third round: the Codex review of PR #136.** Four findings were confirmed, each by a test
that failed before its fix: rows CDX-1 to CDX-4. The whole table was run again on that tree,
and that run is the one recorded here. It turned REV-F6 into a layer: the stamp's own
transaction now re-decides the payment's window under its lock, so the unlocked read after
the download is one line of two. CDX-2 removes the other line and is killed.

TPTG-31 (a) is killed because the sweep, with `SKIP LOCKED` removed, blocks on the row the
acknowledgement holds. The test fails instead of reporting the skip.
