# Bot text audit — batch 2026-10-10 (FIX-07)

What changed in the Persian defaults (`packages/i18n/src/catalogue.fa.ts`), why, and what a
rolling update or a rollback does with it. Source: the owner's brief for this batch (§C2–C7,
"brief C#" below) and the read-only audit of `main@9e604def` (`audit_botux`, "audit" below).
Baseline of every "current" text: `main@9e604def`.

Pinned by `tests/unit/text-audit-2026-10-10.test.ts`: a render matrix over every key below
(valid body, no literal `{token}` or `{icon:…}` with all or only the required values, under
4096, Persian letters, «شما» not «تو») and one meaning pin per defect. Each meaning pin was
mutation-checked: with the `main@9e604def` catalogue restored, every one of them fails.

## Rollback compatibility, once for every row

Unless a row says otherwise, a change here is a change of DEFAULT text only:

- no placeholder was added to or removed from any contract (`packages/contracts` untouched in
  this part), so every stored `template_overrides` row still validates and renders exactly
  as before — an operator's override of a changed key keeps the operator's wording;
- the catalogue ships inside the image, so during a rolling update an old replica renders its
  own old default and a new one the new default; after a rollback every replica renders the
  old default. Nothing is stored, so nothing needs undoing;
- every `{icon:…}` slot used is one `APPEARANCE_SLOTS` already declared (`purchase`,
  `service`, `date`, `traffic`, `amount`, `time`, `warning`), so an override that adopts one
  is valid on the old release too.
