# Round T (T2) — reply-keyboard wire falsification record

Each rule below was reverted alone in the T2 worktree, against its own database
(`nexa_test_t2`), with no other suite running against it. Only the named tests were run
(`vitest -t`), and the mutated file was restored with `git checkout` and checked byte for byte
(SHA-256 against the committed file) before the next mutation. Every cited test passes on the
unmutated tree. `docs/round-t-button-builder-audit.md` §13 (T2) names the targets; owner rule
B5 (audit §12, T2; `OQ-T-API-02`) is the fallback rule rows T2-04 to T2-09 and T2-13 hold.

The unit suite stubs `fetch`; the integration suite drives the real app against the shared
HTTP fake (`tests/support/fake-telegram-bot-api.ts`, which models `sendMessage` from round T).
Both can only prove that this code and these fakes agree. What Telegram itself does is the
real-bot acceptance checklist in the audit's T2 notes (R-ACC-1..3), and the exact refusal an
ineligible bot gets for an icon is `OQ-T-API-05`.

**Amended 2026-10-02.** The owner retired the builder's button icon
(`docs/round-t-button-builder-audit.md` §16): the main menu no longer feeds the transport an
icon, so the END-TO-END icon cases of `telegram-reply-keyboard.test.ts` were replaced and their
citations are removed from the rows below. The transport's icon handling is unchanged and the
unit citations (`telegram-reply-keyboard-wire.test.ts`, which drives the messenger with its own
menu stub) stand as recorded.

not the text the iconed button carried, so a label prefixed on the wire still routed in the
