# Legacy migration — production readiness gate (Item 17)

The program's rule: the migration is **READY_FOR_PRODUCTION_APPROVAL** only when every gate
below is satisfied by its named evidence artifact. Then it **stops**: readiness is not
approval, and approval is the owner's alone, given at cutover step 13 for one specific run
([`cutover-runbook.md`](cutover-runbook.md)). Nothing in this repository tags, releases,
deploys or imports into production.

A gate is satisfied by an **artifact a reviewer can open** — a merged commit, a CI run, a
filled result table, a report file — never by a statement that something was done. A
synthetic run satisfies only the gates that say so; it never satisfies a gate that asks for
real data.

**Status when written: NOT READY.** Every gate needing a real legacy archive, RickPanel or a
staging server is open, by construction, in this environment.

## What the synthetic run is for

`scripts/legacy-rehearsal.sh --evidence-class synthetic` on the IMPORTER's fixture under
`tests/fixtures/legacy/` proves that the harness, the reconciliation SQL and P7's code agree
with each other end to end, including the interrupt, the resume and the rollback mechanism.
It is a precondition for running G11 (there is no point taking a staging window to find a
harness bug), and it appears in the readiness record as exactly that — never in place of
any gate marked **no** above.

## Recording the decision

When every gate is satisfied, the readiness record is one commit adding a filled copy of the
table above (artifact links in the second column) and the line:

> READY_FOR_PRODUCTION_APPROVAL — `<main commit>`, `<release version>`, `<date UTC>`.

Then stop. The next action is the owner's: scheduling the window and, at cutover step 13,
approving one run that names its backup id and source fingerprint.
