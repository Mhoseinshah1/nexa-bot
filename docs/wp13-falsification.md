# WP13 bots management — falsification record

Each rule reverted ALONE against the integration branch, the named test file run (the
integration ones against a freshly created test database), and the file restored
byte-for-byte; the driver refuses to continue if `git diff` of the mutated file is not empty.

B13-11 and B13-12 hold the Web Admin's wiring of the token-replacement affordance to
`settings.destructive`, and had no test until this pass. B13-13 to B13-14u are the fixes
from the read-only hostile review of this package (a reused key reporting another token as
replaced; a foreign webhook URL shown verbatim), each written with the test it cites.

B13-15 to B13-19 are the four findings of the one Codex review of this package (on
`4359717`), each confirmed and fixed: a replay that re-read the bot instead of returning
its first result, a same-token no-op decided before the lock, a token validated before
the permission, and a live check left standing after the token or status it described
changed.
